**Suggestions**

These are beyond the requested visual specification and remain unimplemented:

- **Fix the rounded-rectangle helper’s radius contract.** `round_fill` passes its `radius` directly to GDI’s ellipse-width/height parameters. A nominal 4px radius therefore produces approximately a 2px radius. Changing this blindly would also affect switches, whose calls currently rely on diameter-like values. Separate radius and diameter semantics first. [paint.rs:1872](C:/Users/thurs/tools/taskbar-dock/src/settings_app/paint.rs:1872), [RoundRect documentation](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/nf-wingdi-roundrect)
- **Use explicit font styles instead of size-plus-bold inference.** `aligned_text` sends almost every bold request to the 14px semibold slot, regardless of the requested size. Adding a 28px constant alone will not guarantee a 28px heading. An explicit style/font-slot parameter would prevent this. [paint.rs:1954](C:/Users/thurs/tools/taskbar-dock/src/settings_app/paint.rs:1954)
- **Review the permanently reserved Reset space.** `row_rects` subtracts Reset width and gap even when Reset is invisible. That wastes 64px at 100% scaling. If reset moves to overflow, reclaim it consistently across rows. [layout.rs:709](C:/Users/thurs/tools/taskbar-dock/src/settings_app/layout.rs:709)
- **Give the settings app its own Fluent geometry policy.** Existing widget guidance deliberately uses Apple-inspired proportional corners. Applying that policy to this settings window would conflict with the requested Windows look. Document the app-specific fixed-radius tokens. [UI-RULES.md:7](C:/Users/thurs/tools/taskbar-dock/UI-RULES.md:7)

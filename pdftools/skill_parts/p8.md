## PDF to Markdown

- Confirm the user wants a Claude-project Markdown source and identify the destination folder before conversion. Use `pdf.cmd md FILE --list` to show the chapter plan and estimate; `--level auto` or `--chunk N` changes planning, and `--parts` selects listed part numbers. Then run `pdf.cmd md FILE`; use `-o FOLDER` for a specific output place. `md` resumes completed parts, and `--force` reconverts them. `--no-read` keeps the run local and leaves equations marked as unread. Passwords use `--password-file` or `--password-env`.
- Run `md` in the background when its estimate exceeds 90 seconds. The verdict is final: do not read crops, sheets, chapter `.md` files, or full pages. Report the `mdexport` approximate tokens per file and the doubtful-equation and QA-likely counts. A wrong result is a pdftools bug to fix; then rerun the command.
- `pdf.cmd mdread FOLDER` reads unread or doubtful equations and reruns QA. `pdf.cmd mdqa FOLDER` reruns QA only. `pdf.cmd mdfix FOLDER FIXES` applies the pdf2md fixes format; `--dry-run` validates without changing Markdown, and unmatched blocks are logged in `review_notes.md`.
- `pdf.cmd mdexport FOLDER` writes lean project files to `<folder>_project`; `-o` changes that destination, `--title` sets the source name, and `--skip` omits named files (default `index`). Its result reports approximate tokens per file. Use the exported files as project sources, not the conversion intermediates.
